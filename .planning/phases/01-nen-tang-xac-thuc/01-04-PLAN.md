    List<LoginAttempt> recent = loginAttemptRepository.findTop5ByEmailOrderByAttemptedAtDesc(email);
    if (recent.size() < 5) return false;

`login(LoginRequest req, String ipAddress, String userAgent)`:
1. `email = req.email().toLowerCase()`. Kiểm `isLockedOut(email)` → nếu true, ném `BusinessException("ACCOUNT_LOCKED", 403, "Tài khoản tạm khoá do đăng nhập sai nhiều lần.")` — **ném TRƯỚC khi kiểm password, không ghi thêm login_attempts khi đã khoá** (tránh vòng lặp vô hạn kéo dài thời gian khoá).
2. `userOpt = userRepository.findByEmail(email)`. `passwordOk = userOpt.isPresent() && passwordEncoder.matches(req.password(), userOpt.get().getPasswordHash())`.
3. Ghi `LoginAttempt` MỚI (email, ipAddress, succeeded=passwordOk, userAgent, attemptedAt=now) — LUÔN ghi kể cả email không tồn tại.
4. Nếu `!passwordOk` → ném `BusinessException("INVALID_CREDENTIALS", 401, "Email hoặc mật khẩu không đúng.")` — **CÙNG message dù lý do là sai email hay sai password.**
5. Nếu đúng: `user.setLastLoginAt(Instant.now())`, save. Sinh token như register (bước 4-6), KHÔNG tạo ví mới.

`refresh(RefreshRequest req)`:
1. `hash = sha256Hex(req.refreshToken())`.
2. `activeOpt = refreshTokenRepository.findActiveByTokenHashForUpdate(hash)` (PESSIMISTIC_WRITE — xem Repository ở trên).
3. Nếu rỗng: tra `refreshTokenRepository.findByTokenHash(hash)` (không lock) — nếu tồn tại (nghĩa là đã bị revoke trước đó, đang bị dùng lại) → `revokeAllActiveForUser(anyOpt.get().getUserId())` (AUTH-03 reuse detection). Ném `BusinessException("REFRESH_TOKEN_INVALID", 401, "Thẻ làm mới không hợp lệ.")` trong CẢ HAI trường hợp (tồn tại hay không tồn tại — tránh lộ thông tin).
4. Nếu có `current`: kiểm `current.getExpiresAt().isBefore(Instant.now())` → nếu hết hạn, ném `REFRESH_TOKEN_INVALID` tương tự (không cần revoke gì thêm vì token đã hết hạn tự nhiên, không phải dấu hiệu bị đánh cắp).
5. Rotation: `current.setRevokedAt(Instant.now())`, save. Sinh `newRawToken`, lưu `RefreshToken` mới cùng `userId`.
6. Lấy lại `User` (cần cho `plan`) qua `userRepository.findById(current.getUserId())`, sinh access token mới.
7. Trả `RefreshResponse`.

`logout(String rawRefreshToken, boolean logoutAllDevices)`:
1. `hash = sha256Hex(rawRefreshToken)`.
2. Nếu `logoutAllDevices`: tra token để lấy `userId` (`findByTokenHash`), gọi `revokeAllActiveForUser(userId)`.
3. Ngược lại: `revokeByTokenHash(hash)`.
4. Không ném lỗi nếu token không tồn tại/đã revoke (logout idempotent về mặt hành vi — trả 200 rỗng theo `api/01` mục 4).

**Helper** trong `AuthService` hoặc class `TokenUtil` riêng:
```java
private static String sha256Hex(String raw) {
    try {
        MessageDigest digest = MessageDigest.getInstance("SHA-256");
        byte[] hash = digest.digest(raw.getBytes(StandardCharsets.UTF_8));
        return HexFormat.of().formatHex(hash);
    } catch (NoSuchAlgorithmException e) {
        throw new IllegalStateException(e);
    }
}

private static String generateSecureRandomToken() {
    byte[] bytes = new byte[32]; // 256-bit
    new SecureRandom().nextBytes(bytes);
    return Base64.getUrlEncoder().withoutPadding().encodeToString(bytes);
}
```

**`ClientIpResolver.java`** (package `common.security`) — helper lấy IP thật từ request, ưu tiên header `X-Forwarded-For` (nếu có proxy) rồi fallback `request.getRemoteAddr()`:
```java
public final class ClientIpResolver {
    private ClientIpResolver() {}
    public static String resolve(HttpServletRequest request) {
        String forwarded = request.getHeader("X-Forwarded-For");
        if (forwarded != null && !forwarded.isBlank()) {
            return forwarded.split(",")[0].trim();
        }
        return request.getRemoteAddr();
    }
}
```
